## Module Contract

The heartbeat monitor has five signals:

| Signal | Direction | Behavior |
|---|---|---|
| `clk` | input | State is sampled or updated on its rising edge. |
| `rst_n` | input | Active-low asynchronous reset. |
| `heartbeat` | input | A high level sampled on a rising edge is a valid heartbeat. |
| `clear_timeout` | input | Synchronously clears the timeout and restarts its interval. |
| `timeout` | output | Latched fault level after the configured number of missing-heartbeat cycles. |

`TIMEOUT_CYCLES` is expressed in clock cycles instead of milliseconds so the
module does not silently assume a final clock frequency. Its default value is
25,000,000 cycles, which corresponds to 500 ms only when the integration clock
is 50 MHz. The testbench overrides it with five cycles for fast simulation.

The complete behavior and current assumptions are recorded in
[`../HEARTBEAT_MONITOR_SPEC.md`](../HEARTBEAT_MONITOR_SPEC.md).

The RTL uses an automatically calculated counter width. With
`TIMEOUT_CYCLES = 5`, the counter holds values 0 through 4. On the fifth
consecutive missing-heartbeat edge, `timeout` asserts and the counter remains
at 4. This avoids an unnecessary sixth counter state.

Priority is:

1. asynchronous reset;
2. heartbeat or explicit clear;
3. timeout boundary detection;
4. normal counter increment.

## Self-Checking Testbench

The testbench automatically checks:

- known output state during reset;
- no early timeout at `N-1` missing cycles;
- timeout assertion on exactly the `N`th missing cycle;
- periodic heartbeat operation;
- latched timeout behavior;
- recovery through a new heartbeat;
- recovery through `clear_timeout`;
- a complete post-clear interval;
- asynchronous reset while timeout is active.

Heartbeat and clear pulses begin on falling clock edges. This keeps stimulus
stable before the following rising edge and avoids a testbench/DUT race at the
sampling edge.

## Problems Encountered and Resolved

### Questa language option

The first script used `vlog -2001`, which this Questa release does not accept.
The supported strict compatibility option is:

```text
vlog -vlog01compat -lint=full
```

After correction, both modules compiled with zero errors and zero warnings.

### Simulator license checkout

Verilog compilation succeeded before the simulator license was configured, but
elaboration and simulation could not start. This demonstrated an important
evidence boundary: compilation success is not simulation success. A free
node-locked Questa Starter license was obtained and configured locally; the
license file is not part of the repository.

### Optimized signals missing from the Wave window

The first GUI run loaded an optimized design and the waveform script could not
find `clk` or other internal objects. The simulation was reloaded with:

```text
vsim -onfinish stop -voptargs=+acc work.tb_heartbeat_monitor
```

`+acc` preserves signal accessibility for debugging. This improves
observability at the cost of some simulation optimization. The reusable GUI
launcher now includes this option.

## Lessons Learned

- A simulator may compile Verilog without being licensed to elaborate and run
  the design; the verification status must record these as separate gates.
- A passing self-checking testbench is stronger evidence than waveform viewing
  alone, while waveform inspection remains valuable for understanding timing.
- Simulator optimization can hide signals. Debug accessibility should be
  enabled deliberately rather than assumed.
- Timeout boundaries must be defined in sampled clock cycles to prevent an
  off-by-one disagreement between the specification, RTL, and testbench.
